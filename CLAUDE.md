# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

Package manager is Yarn (`yarn.lock`; CI runs `yarn install`), but scripts are invoked via `npm run`.

- `npm run dev` — Next.js dev server (Turbopack)
- `npm run build` / `npm run start` — production build / serve
- `npm run lint` — ESLint (`next/core-web-vitals` + `next/typescript`)
- `npm run format` — Prettier write
- `npm run spotless` — `lint --fix` then `format`; this is what the PR CI job (`.github/workflows/pr.yml`) runs

There is no test runner or `test` script. The CI test step only runs when `RUN_TESTS=true`, and would fail as-is.

Prettier style: single quotes, semicolons, trailing commas, 100-col width, LF line endings.

## Architecture

This repo is **frontend only**: a Next.js 15 (App Router, React 19, TypeScript, Tailwind v4) storefront and seller centre branded "NextPower". All data comes from the NestJS API in `../server` (run it alongside; see below). The README describes a Django/DRF backend, Stripe/PayPal and JWT auth: that backend was never built.

### Route prefix and the shared seller centre
- This app holds NextPower's shop and the **seller centre every store uses**. The backend in `../server` serves many sellers; each has its own shop, and they all manage their store in the same seller centre. `../server/PLAN.md` step 14 plans per-seller shop apps in a monorepo, with NextPower served from `/`.
- NextPower's shop and customer account sit in a `next-power` route segment and component folder: routes in `src/app/next-power/` (URLs `/next-power/...`, with its own `layout.tsx`, `not-found.tsx` and `icon.svg`), components in `src/components/next-power/`.
- The seller centre is `src/app/admin/` with `src/components/admin/`, and has nothing NextPower-specific. `/admin` lists the stores this browser has managed (`storeMemory.ts`) and opens any other by its address; `/admin/<store>/...` is one store's seller centre, where `<store>` is the store's slug (`next-power`) or a domain of its own. `[store]/layout.tsx` fetches the store's public profile on the server (`lib/api/serverStore.ts`) for the tab title and icon, and renders `AdminApp`: one React Query cache per store, the store context (`adminStore.ts`: `useAdminHref()` makes links inside the store's seller centre, `useStorefrontUrl()` links to its shop), and the store's colours. `(panel)/layout.tsx` adds `AdminShell` (sidebar with the store's name and logo, menu from `nav.ts`, account and sign-out; a top bar and slide-out menu on phones) and `RequireStaff`; `login/` is the store-branded staff sign-in; `print/invoices` is the bare invoice page. Old `/next-power/admin/*` and `/next-power/print/*` addresses redirect there (`next.config.ts`).
- Store colours: `lib/storeTheme.ts` turns the store's `brandColor` (Settings → Brand colour) into the brand tokens (`--color-brand*`, `--primary`, `--ring`, `--gradient-brand`, `--brand-shadow`, `--chart-current`, the heat ramp) for light and dark, darkening a colour just enough for white text to stay at 4.5:1. `AdminApp` renders them as a `<style>` while the seller centre is open. Use the brand tokens (`bg-brand`, `text-brand`, `var(--color-brand)`) rather than fixed blues in the seller centre, so it follows each store.
- Shared building blocks used by both the shop and the seller centre live in `src/components/common/` (Panel, PageHeading, QueryState, RequireAuth, BackButton, UserAvatar, Rating, ThemeToggle, DashboardCard, `orders/`, `reviews/`, `chat/`). Keep them free of NextPower links: `RequireAuth` takes its `loginHref`.
- Elsewhere: the root `src/app/layout.tsx` (html/body, Geist font, theme script, `globals.css`), `src/components/ui/` (shadcn primitives, imported as `@/components/ui/...`), `src/components/invoice/` (the printable invoice, with no store-specific code), plus `src/docs/`, `src/redux/`, `src/lib/` and `src/types/`.
- Links are literal paths with the prefix (`/next-power/products`), including `pathname` checks. `src/app/page.tsx` redirects `/` to `/next-power`. Unknown `/next-power/...` paths hit `app/next-power/[...missing]`, which shows the store's 404 inside its layout. Any other unknown path gets the plain root `src/app/not-found.tsx`.

### Data comes from the API (React Query)
- The NestJS API in `../server` is the source of truth. `src/lib/api/client.ts` calls `NEXT_PUBLIC_API_URL` (`.env.local`, default `http://localhost:5000/api/v1`) with the `X-Seller-Host` header (`NEXT_PUBLIC_STORE_HOST`), the bearer token and the guest token; the session and guest token live in localStorage (`np.session`, `np.guestToken`). The store a request is for comes from the page: `/admin/<store>/...` pages talk to that store (`currentStoreHost()`, `storeHostFor()`; `NEXT_PUBLIC_PLATFORM_DOMAIN`, else the store host without its first label), every other page to this app's own store. Sign-ins are kept per store (`np.session` for NextPower, `np.session:<host>` for others), so one browser can manage several stores at once; guest carts only exist for the own store. It refreshes the access token once on a 401, and `uploadImage` turns a picked image (data URL) into an upload URL. `src/lib/api/types.ts` holds the API shapes and `mappers.ts` turns them into the UI types in `src/types/` (ids are strings/UUIDs).
- **Server data goes through TanStack Query.** `src/lib/query/` has one file of hooks per area: `shop` (store, delivery options, categories, public coupons), `catalog` (whole catalogue, one product, save/delete/bulk), `cart`, `wishlist`, `account` (sign-in/out, profile, password), `addresses`, `orders` (customer orders, checkout), `reviews` (reviews, photos, comments), `messages` (contact/feedback, customer chat) and `admin` (orders, invoices, analytics, settings, domains, delivery options, coupons, reviews, users, messages, chats). Query keys are in `keys.ts`; components call the hooks and never `fetch` themselves.
- Mutations show their error as a toast (the `MutationCache` in `lib/query/client.ts`) unless they pass `meta: { toast: false }` and show it themselves. 4xx errors aren't retried.
- `lib/query/session.ts` `useSession()` gives the signed-in user (`ready` turns true once the browser has read the session) and `isStaff`. `components/next-power/Providers.tsx` resets the whole query cache when the user changes, so nothing from the last person shows.
- The catalogue is fetched whole (100 per page) and filtered in the browser; a store has about 1k products. Orders, reviews, users and messages are paged by cursor on the server (`useInfiniteQuery`, "Load more").
- `src/docs/` still holds TypeScript constants (not documentation) for copy only: site text and fallbacks (`site.ts`; contact details come from the store via `lib/query/storeInfo.ts`), info pages, the account menu (`navLinks.ts`) and the dashboard sidebars (`dashboard.tsx` → `SidebarItems`). The catalogue itself is seeded into the API from `../server/prisma/seed-data/next-power.json`, and the home page from `next-power-home.json` next to it.
- **The home page comes from the API** (`GET /store/home`, types `ApiHomePage` in `lib/api/types.ts`). `app/next-power/page.tsx` fetches it on the server (`fetchHomePage`, so the hero arrives with the HTML) and `components/next-power/home/Home.tsx` renders the hero, then each visible section by `type`. Section components take their content as props; `home/media.ts` turns stored links (shop paths without `/next-power`, or https) into hrefs and decides which images next/image may optimise (`unoptimized` for hosts outside `remotePatterns`). Icons are names mapped in `components/common/homeIcons.tsx`. Several banners become a Swiper carousel with a pause button; a combo adds all its products to the cart and shows the coupon that gives the combo price.
- Remote images are allowed from `en.goodwe.com`, `en.pvbm.com`, `images.unsplash.com` and the API host (`/api/v1/uploads/**`) in `next.config.ts` `images.remotePatterns`; add any new image host there.

### State: Redux Toolkit (client state only)
- `src/redux/store.ts` has one slice, `checkout` (delivery option, coupon and what it takes off, installation), chosen in the cart and used at checkout. `Providers.tsx` keeps it in sessionStorage through a reload. Use `useAppDispatch` / `useAppSelector` from `src/redux/hooks.ts`.
- `Providers` (client component) wraps the NextPower UI in `src/app/next-power/layout.tsx` (QueryClientProvider + Redux), together with its `Navbar`, `Footer`, `SunLight`/`GridPulses` and the `react-hot-toast` `Toaster`.

### Routing
- Public storefront routes sit at the top of `src/app/next-power/` (URLs `/next-power/...`): `products`, `products/[id]`, `categories`, `deals`, `cart`, `checkout` (cash on delivery; `order-summary` redirects there), `login`, `orders`, `wish-list`, `chat`, `contact`, `profile/*`.
- Invoices print from `/admin/<store>/print/invoices?ids=<id,id>` or `?status=PROCESSING`: A4 sheets (`components/invoice/InvoiceSheet.tsx`: parcel label on top, invoice below, Code 128 barcode and a QR code to the order in the store's shop); `&print=1` opens the print dialog once they have loaded. Orders link there from the order page, each row, and "Print packing invoices".
- Signed-in customer pages are guarded by `components/common/RequireAuth.tsx` with `loginHref="/next-power/login"` (in `AccountShell`, `DashboardLayout` and the chat). The seller centre uses `components/admin/RequireStaff.tsx`: owners and managers only, sign-in at `/admin/<store>/login`.
- Static information pages (`about`, `shipping`, `returns`, `faq`, `privacy`, `terms`, `cookies` under `/next-power/`) are one route, `src/app/next-power/(info)/[slug]/page.tsx`, with copy in `src/docs/infoPages.ts`. Add a page by adding an entry there.
- The seller centre (`/admin/<store>/*`) has the dashboard, products (form, bulk editor), categories, orders, payments, customers and team, reviews, coupons, chats, messages, the home page editor (`components/admin/homePage/`: the page as shoppers see it, each section rendered by the shop's own components inside an `inert` preview with a toolbar on top: drag grip (`useDragSort.ts`, pointer events, so touch works too; auto-scrolls at the window edges), shown switch, arrows, Edit (a side sheet with the section's form; the preview updates as you type) and delete. One draft of the whole page, saved with PUT; images are uploaded during the save; `pageProblems` lists what is missing before the API is asked) and settings (store details, brand colour, checkout, invoices, alerts, delivery, domains). The customer's dashboard, `(client)` → `/next-power/client/*`, uses `src/components/next-power/DashboardLayout.tsx` (menu in `docs/dashboard.tsx`); it and the account pages (`profilePages/AccountShell.tsx`) share `components/next-power/shared/SideNavShell.tsx`: a sidebar on desktop, a scrolling tab row on mobile.
- Dashboard pages are built from `components/common/Panel.tsx`, `components/common/DashboardCard.tsx` (stat tile) and `components/common/PageHeading.tsx`.
- Admin add and edit product share the Shopify-style `components/admin/Products/ProductForm.tsx`; its cards, yup schema and form↔product mapping live in `components/admin/Products/productForm/` (`formModel.ts`). The add page (`AddProduct.tsx`) reads `?duplicate=<id>` and an `n` nonce, and keys the form on them so "Save and add another" / "Save and duplicate" get a fresh form.

### Products: rich text, variants, drafts
- Descriptions are HTML from the Tiptap editor in `components/next-power/RichTextEditor/` (custom image node view for resize and alignment). Render them only through `descriptionToHtml()` in `lib/richText.ts`, which sanitises with `xss`; use `excerpt()` / `htmlToText()` for plain text. Shared typography is the `.rich-text` class in `globals.css`.
- Variants are `product.options` (`{ name, values: { label, priceDelta, swatch?, image? }[] }`). An option named Color/Colour shows swatches, and a value's `image` makes the product gallery jump to that photo. Price and cart helpers (`variantPrice`, `toCartItem` with a selection, `priceRange`) are in `lib/products.ts`; the cart sends the variant label and the API reprices it.
- `status: 'draft'` or `'archived'` hides a product from the storefront: storefront lists use `useStoreProducts()` (active only), the seller centre `useCatalog()` (everything staff may see).
- Picked images are downscaled to data URLs (`lib/imageFile.ts`), then uploaded with the save (`uploadImage` → `POST /uploads`); the API stores the returned `/api/v1/uploads/<id>` URL.
- Pages in `src/app` are thin wrappers. The real UI lives in `src/components/next-power/<feature>/` (e.g. `components/next-power/products/productDetails/`) and, for the seller centre, `src/components/admin/<feature>/` (e.g. `components/admin/Products/`). Most feature components are client components.

### UI conventions
- shadcn/ui ("new-york" style, lucide icons) primitives are in `src/components/ui/`. Add new ones with the shadcn CLI per `components.json`. Path alias `@/*` → `src/*`.
- `cn()` and shared helpers such as `getStatusIcon` and `capitalize` are in `src/lib/utils.tsx` (note the `.tsx` extension, because it returns JSX).
- Custom Tailwind colors (`brand`, `brand-hover`, `brand-soft`, `brand-ink`, `sun`, `sun-soft`, `sun-ink`, `page`, `green`, `hGreen`, `red`, `yellow`, `black`) are defined in the `@theme` block of `src/app/globals.css`. Filled `bg-brand` / `bg-primary` surfaces also get `--gradient-brand` from a components-layer rule. Tailwind v4 has no `tailwind.config`.
- Forms use `react-hook-form` + `yup` (`@hookform/resolvers`). Tables use `@tanstack/react-table` via `components/next-power/DataTable.tsx`. Charts use `recharts`.
- Shared TypeScript types are in `src/types/` (`api_types.ts` holds `IProduct`, `ICartItem`, etc.).

### Dark mode
- This uses Tailwind's class strategy: `@custom-variant dark (&:where(.dark, .dark *))` in `globals.css`. An inline script in `src/app/layout.tsx` sets `.dark` on `<html>` before paint, from `localStorage.theme` or the system setting. `components/next-power/shared/ThemeToggle.tsx` provides the desktop navbar icon button (default export) and the mobile menu's `ThemeSwitch` row, built on the shadcn `Switch`. Both stay in sync by watching the html class.
- Component colours come in pairs: every hardcoded light colour has a `dark:` partner next to it (`bg-white dark:bg-slate-900`, `text-gray-900 dark:text-slate-100`, `border-gray-200 dark:border-white/10`). Add the partner when adding a new neutral or status colour. Shared values switch in the `.dark { }` block of `globals.css`: the shadcn tokens, the `@theme` colours above (`brand` becomes a lighter blue for text), shadows, and the chart colours `--chart-*` (`components/next-power/admin/DashboardContent/chartKit.tsx` passes them to Recharts as `var(...)`). The `glass`/`glass-card` utilities carry their own `@variant dark`.
- Precedence pitfall: Tailwind emits `dark:` rules after plain and `md:`/`lg:` utilities. In `cn('bg-white dark:bg-slate-900', active && 'bg-brand')`, the dark partner wins over `bg-brand` in dark mode. Use a ternary, or give the override its own `dark:` copy. State variants (`hover:`, `aria-*:`, `data-*:`) are unaffected because they are more specific.
- Light mode must not change when you touch dark styles: keep the light class and add or change only `dark:` classes.
